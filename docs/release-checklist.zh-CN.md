# 发布指南

[English](release-checklist.md) · [开发说明](development.zh-CN.md)

每次发布对应一个审阅后的源码提交和一个冻结包。

## 准备

1. 完成计划内修改，修复影响它们的失败。
2. 同步中英文说明、版本标识、兼容性和更新记录。
3. 运行受影响测试与最终候选检查，对输入相同的结果直接复用。
4. 检查文档渲染、链接、包内容、运行依赖，以及待推送 Git 变更中的私密资料。
5. 提交源码、文档和生成的 `lib/`。
6. 执行 `node scripts/freeze-local-candidate.mjs <version>`，保留 tgz 和清单原始内容。
7. 在支持的宿主中安装该包，重启后确认实际加载版本。

alpha.3/RC5 × Web/Desktop 使用同一个文件。固定源码的 alpha.3 桌面构建应注明未签名。文档变更只确认新包安装和加载，之前的行为结果保留其原始版本身份。

## 发布到 GitHub

推送审阅后的提交，等待对应 CI 通过。失败时先修正原因，再创建版本标签。

在该提交创建标签，准备 GitHub Release 草稿，附上简洁的中英文说明、冻结 tgz 和校验文件。RC 版本标记为预发布，核对上传资产后再公开 Release。

过程日志、设备记录、认证数据和本地报告不进入 Git 或 Release 附件。公开内容包括插件包、校验值和用户文档。

## 发布到 npm

明确本次要更新的 npm 标签，使用拥有包发布权限的账号完成认证。

```sh
npm publish <frozen-file.tgz> --tag next --access public
```

将注册表中的 tarball 下载到独立目录，与冻结文件比较 SHA-256 和 integrity。只有发布决定包含 `latest` 时才更新该标签。

GitHub 与 npm 可以分开发布。恢复中断的发布流程前，先读取各渠道的真实状态。

## 保留版本

已发布版本的内容不可修改，包内容变化使用新版本。本地保留旧包，并明确每个版本所对应的检查。
