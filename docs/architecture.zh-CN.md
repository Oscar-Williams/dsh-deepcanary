# 架构

[English](architecture.md) · [文档目录](README.zh-CN.md)

DSH 公开事实依次经过 Provider、确定性规则、投递策略和收件箱。Provider 选择事实，核心负责提醒判定，客户端展示状态并提交提醒动作。

## 任务标识

任务具有 `taskRef` 和 `executionGeneration`。原生子代理父子关系及 Job 归属组成任务分组，fork 保留独立身份。每个人工事项有自己的 `humanActionRef`，处理一项审批不会关闭另一项。

序号水位用于区分执行并拒绝过期回调，fork 继承的历史不会产生新提醒。

自动化运行关联调度触发、目标会话、投递消息和已接收轮次，只有匹配的执行可以结算该次运行。投递、运行、完成、失败、取消和未知分别记录。

## 提醒等级

| 等级 | 判定依据 |
| --- | --- |
| C3 | 当前有效的权威问答或审批阻塞进度 |
| C2 | 已观察到的失败或异常状态需要检查 |
| C1 | 有信息性更新可供查看 |
| C0 | 正常工作无需关注 |

定时问答使用 DSH 的问题投影。阻塞问题为 C3，前台等待超时后成为继续保留的 C1 事项；已接收的答案关闭对应调用。仅有排队输入不足以证明新执行已被接收。

明确的 `turn/end` 结果 `aborted → user` 安静地进入动态。未知中止保留 C2，仅有 `ABORTED` 错误码不能证明用户主动取消。

## 持久化与动作

元数据存储以原子方式写入 schema 2，并迁移 schema 1，保留稍后安排、通知代次、去重、预算和认领。损坏或不支持的数据会保留并报告。

状态归属于 profile 与插件实例，账本由一个生命周期写入者持有。连续保存请求会合并，通知授权等待真实的持久化结果。

协议 3 的动作携带请求 ID、预期 revision 和执行代次。重复动作返回已有回执；过期状态返回 HTTP 409，客户端刷新时保留草稿。通知回调还检查 `notificationGeneration`。

收件箱最多保留 500 项，优先保留人工事项与明确安排的提醒。受保护事项占满容量时，保留尚未读取的源水位并报告覆盖不完整。后台观察和自动化历史各自限制为 256 条。

## 客户端与投递

待处理、稍后和动态使用同一宿主快照。面板支持列表与详情布局、指针捕获、可视区域约束、键盘编辑和取消，布局保存在设备本地。

构造通知前，必须先持久化对应代次的认领和预算。构造、投递、可见和点击分别观察，原生任务的完成状态仍由 DSH 管理。

宿主菜单、设置贡献、订阅及 effect 随所属对象释放，集成入口见 [DSH 公开接口](dsh-surface-audit.zh-CN.md)。
