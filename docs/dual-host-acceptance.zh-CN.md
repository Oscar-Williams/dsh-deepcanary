# Web 与桌面测试

[English](dual-host-acceptance.md) · [开发指南](development.zh-CN.md)

为每个 DSH 版本使用隔离 home，并分别设置 Web 与桌面 profile。日常数据与测试 profile 分开保存。同一个冻结 tgz 安装到四种组合：alpha.3、RC5 各自的 WebUI 和 Windows 桌面版。

## 安装与启动

确认宿主接受插件包，冷启动后正常激活，显示版本与包版本一致。桌面测试应区分官方应用与固定源码构建。修改持久化或迁移逻辑时，使用已有提醒状态检查升级。

官方 alpha.3 桌面包不可用时，从固定源码的 `apps/desktop` 构建并测试，准确注明结果来自未签名的本地构建。

## 按修改选择检查

| 修改范围 | 应覆盖的行为 |
| --- | --- |
| 人工事项 | 提问、超时、迟到回答、审批及独立闭合 |
| 任务归属 | 根任务、子任务、Job、fork、复用会话的自动化 |
| 持久化 | 已有状态迁移、重启、写入失败与恢复 |
| 并发操作 | 两个页面、过期 revision、重复操作与草稿保留 |
| 通知 | 前后台、桌面最小化与隐藏、点击和失效目标 |
| 界面 | 浅深主题、窄布局、键盘、拖动、缩放和页面缩放 |
| 鉴权 | 已认证请求成功，未认证请求被拒绝 |

修复受影响行为中的缺陷后，重跑对应用例。输入没有变化的成功结果可以复用。仅更新文档或版本时，确认安装与实际加载身份，无需重复全部交互检查。

## 通知生命周期

保持宿主与渲染进程运行。分别检查真实系统横幅、点击与内部投递事件。点击应选中当前提醒和正确会话；目标已删除时，应留在收件箱并显示明确提示。

桌面窗口最小化或隐藏时，应用可以继续运行；完全退出后插件停止。浏览器和 Windows 权限、勿扰、静默时段及提醒预算均会影响投递。

## 本地保存测试数据

宿主身份、包哈希、测试结果、截图和诊断日志保存在 Git 之外。分享问题报告前移除私有对话与认证信息。

受控样本、模拟触控和单一操作系统测试各有适用范围。准确说明未测试的平台与后续宿主版本。
